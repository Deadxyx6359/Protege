# Akira dependencies.
#
# POLICY: every dependency is justified below. Anything that performs network
# I/O as part of normal operation is rejected outright. Installing these
# packages is the ONLY step in this project's lifecycle that touches the
# network; after install, `verify_offline.py` proves the runtime import graph
# contains no networking module.
#
# Versions are pinned exactly. Do not relax to ranges -- an unpinned transitive
# upgrade is an unaudited dependency.

# --- Runtime -----------------------------------------------------------------

# llama-cpp-python: Python bindings over llama.cpp. This is the entire inference
# stack. Chosen over Ollama/LM Studio because those are servers -- they open
# sockets and expose HTTP endpoints. This binds llama.cpp as an in-process
# shared library via ctypes; no socket is ever created.
#
# 0.3.34 rather than the originally-planned 0.3.2: 0.3.2 ships no prebuilt
# Windows wheel and this machine has no C compiler, while 0.3.34 has a CUDA
# wheel on the cu124 index. Install with:
#   pip install llama-cpp-python==0.3.34 --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124 --prefer-binary
#
# The CUDA wheel needs the CUDA 12 runtime DLLs, which the two nvidia-* packages
# below provide. They land under site-packages/nvidia/..., and cudart64_12.dll,
# cublas64_12.dll and cublasLt64_12.dll must be copied next to llama_cpp/lib/
# llama.dll (one-time step; the README shows the exact command).
llama-cpp-python==0.3.34

# NOTE: llama_cpp.server is a FastAPI/uvicorn HTTP server that ships inside the
# package. We never import it. verify_offline.py asserts it is unreachable from
# our import graph. Do not `pip install llama-cpp-python[server]`.
#
# NOTE: llama_cpp.Llama.from_pretrained() downloads from HuggingFace Hub.
# We never call it. Models are loaded from local paths only.

# CUDA 12 runtime redistributables for the wheel above. Local DLLs only; the
# packages contain no Python code that runs in Akira.
nvidia-cuda-runtime-cu12
nvidia-cublas-cu12

# PySide6-Essentials: Qt 6 bindings. The entire user interface.
#
# Chosen over Tkinter, which cannot do what the interface now has to do: no GPU
# compositing, no scene graph, no real animation, no blur. Chosen over a
# webview shell (Tauri/Electron/pywebview) because those run a browser engine
# in a *separate process*, which no in-process guard can cover -- the same
# reasoning that ruled out Ollama and LM Studio for inference.
#
# Renders through Direct3D11 on the Intel Iris Xe, which drives the display.
# The RTX 3060 stays entirely free for model weights, so the interface costs
# inference nothing.
#
# "Essentials" rather than the full PySide6: it excludes WebEngine (a bundled
# Chromium), Charts, and the multimedia stack. None are wanted here and the
# first is actively unwanted.
#
# HONEST NOTE ON NETWORKING: Qt ships QtNetwork, and QML's `import QtNetwork`
# resolves. We never import either, and verify_offline.py cannot see inside a
# compiled Qt plugin the way it can read Python source -- so for this package
# the check is weaker than it is for the rest of the tree. Qt is also capable
# of calling the OS socket API directly from C++, below anything the Python
# guard patches. The control that actually holds here is the OS firewall rule
# in the README, not the in-process guard.
PySide6-Essentials==6.11.2

# argon2-cffi: argon2id password hashing for the launch PIN. Reference
# implementation of the PHC winner. Pure local computation, no I/O.
argon2-cffi==23.1.0

# PyYAML: parses YAML frontmatter in vault markdown notes. Obsidian writes YAML
# frontmatter, so we must read the same dialect. Used exclusively via
# yaml.safe_load -- never yaml.load -- so no arbitrary object construction.
# Local parsing only, no I/O.
PyYAML==6.0.2

# playwright: drives Chromium, the browser Akira reads pages with (C3). Its
# Python talks to its own driver over pipes and makes no connection itself.
# verify_offline.py lets only akira/core/net/browser.py import it, allows it
# `urllib.parse`, to read addresses, and nothing else from the network, and
# checks that every browser it starts sends everything through Akira's proxy.
#
# The browser is installed once, beside it, like a package (about 115 MB to
# download, 270 MB on disk), and changes only when this is run again:
#   python -m playwright install --only-shell chromium
# It runs in its own process, out of the runtime guard's sight. What holds it
# is the proxy, and the firewall rule in the README holds it harder.
#
# NOTE: Playwright can also make requests from its own driver
# (APIRequestContext, route.fetch), attach to a browser started elsewhere, or
# start one that listens for others. Each would go around the proxy, and
# verify_offline.py refuses them all.
playwright==1.62.0
greenlet==3.5.5
pyee==13.0.1
typing_extensions==4.16.0

# --- Voice (D1, D2) ------------------------------------------------------------

# hand, into models/whisper and models/voice (the README gives the addresses

# verify_offline.py walks all of it from akira/core/voice/engines.py, the one
# module that imports it, and only when voice is first used.

# binding, `_pywhispercpp`. The package's own Python has a model downloader,
